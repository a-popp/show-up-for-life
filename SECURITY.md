# Security Policy

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability. Use GitHub private vulnerability reporting for this repository when it is enabled. If private reporting is not available, contact the repository owner through the GitHub profile associated with `a-popp` and avoid including sensitive details until a private channel is established.

## Credential exposure

If a credential may have been committed or otherwise exposed:

1. Rotate or revoke it immediately at the provider.
2. Treat the exposed value as compromised even if it was deleted later.
3. Assess whether repository history, issues, pull requests, logs, or workflow output also contain it.
4. Clean history only after rotation, using an appropriate history-rewriting process.
5. Document what happened, what was rotated, and any follow-up controls.

## Scope expectations

This project handles sensitive product concepts such as availability, coarse location, relationships, reports, and behavioral follow-through. Security and privacy review should consider misuse, stalking, harassment, coercion, scraping, inference, and unauthorized visibility—not only conventional application vulnerabilities.
